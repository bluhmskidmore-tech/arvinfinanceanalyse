<objective>
Add an explicit, authorized `all_available` rebuild scope that materializes every actual month-end cutoff in the requested year while preserving exact selected-cutoff status and the existing default single-cutoff behavior.
</objective>

<threat_model>
- Reuse the existing `pnl_by_business.adjustment` write authorization; do not add or weaken an authorization path.
- Accept only `scope=selected|all_available`, validate `year`, and reject `as_of_date` outside the selected year.
- Derive batch targets only from actual repository dates in the requested year, keep them unique and sorted, and reject an empty target set; never generate an unbounded calendar range.
- Keep one page-local writer lock around the batch and replace exact `(year, as_of_date)` partitions idempotently; do not change the database schema or shared task framework.
</threat_model>

<must_haves>
- An all-cutoff request for the current 2026 data targets exactly `2026-01-31` through `2026-06-30` in ascending order.
- Re-running a target replaces its exact partition and cannot duplicate rows.
- A historical selected cutoff can see an in-flight all-cutoff batch that includes it, and its status reports that historical cutoff rather than the latest cutoff.
- Omitting `scope` preserves existing `selected` behavior.
</must_haves>
