# Stock Analysis 功能与性能优化基线（2026-07-18）

## 范围与固定协议

- 页面：`/stock-analysis`
- 工作流：首屏 workbench、候选复核队列、深度研究按需加载
- 固定参数：默认 `as_of_date`、`top_k=10`、`sector_window_days=20`、`include=main,evidence_summary`
- 浏览器：Chromium 148.0.7778.96，Windows x64，Node 24.13.0
- 样本：桌面冷启动 5 轮、同上下文暖返回 5 轮、移动冷启动 5 轮
- 移动约束：390×844、4× CPU、150ms RTT、1.6Mbps 下行、750Kbps 上行
- 后端：7 组进程内冷/暖交错样本；冷样本仅清空 workbench 进程内响应缓存
- 基准提交：`855311a7f51aa459afaed2b8a0c141ac29edb58c`；工作区存在未提交的并行修改

## 根因

1. 首屏在 workbench 成功后立即请求 `signal-confluence`，违反“首屏只请求聚合包、重型诊断按需加载”的页面边界。
2. 股票页从 `api/client` 静态导入 `useApiClient`；调用市场数据方法时又落入总客户端，导致首屏下载余额、债券、损益等无关域客户端。
3. 页面生产 CSS 为 640,412B，首屏 CSS 覆盖率约 24.03%；这是后续最大资源热点，但样式规则跨首屏、深度研究和大量覆盖层交织，当前不做无证据删除。
4. 后端不是稳态瓶颈：进程预热后 workbench 冷缓存约 10ms、暖缓存约 2.35ms，线上缓存命中约 1–2ms。

## 本轮改动

- 首屏不再自动请求 `signal-confluence`；用户打开深度研究后才启用该查询和对应 endpoint 状态。
- `clientContext` 为股票分析/Livermore 方法新增按需 market-data 域客户端分流。
- 股票页改从轻量 `clientContext` 导入 `useApiClient`，移除总客户端静态依赖。
- 新增可复跑的生产浏览器采样器、CSS 覆盖率能力和后端 7 轮 profiler。
- 原有闭环结论、阻断、回放和错误态测试改为先打开深度研究，再保持原断言不变。
