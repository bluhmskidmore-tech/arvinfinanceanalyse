## 1. 背景

- 上一轮 R1–R9（Codex 执行）统一了字体族、等宽数字、圆角、控件、子导航和表头，已发布到 5888。单项指标改善了，但整体看仍不像同一个产品。
- 2026-10-02 用 mock 数据在 1440×900 下审计了 21 个路由（只读探针加首屏截图）。结论：问题不在单个组件，而在外壳、规则和执行三层。
  - **外壳**：页面骨架有四种，主区本身被做成了卡片。
  - **规则**：DESIGN.md 原条文鼓励大字号（页标题 24–32px、KPI 28–40px）和按钮 600 字重；微软雅黑没有半粗体，600 一律渲染成粗体，于是满屏粗字。
  - **执行**：页面 CSS 随意覆盖公共样式（857 处 `:has()`、2339 处 `!important`）；同一角色有多套实现（KPI 7 套）；8 页仍挂常态徽标，违反 DESIGN §6。
- 技术栈不需要换。React 18、AntD 5、ECharts 和 ag-grid 是金融工作台的主流组合，问题全部出在呈现层。

## 2. 问题（基线，2026-10-02）

| # | 问题 | 基线（最差页） |
|---|---|---|
| 1 | 骨架有四种，像四个产品 | 浮框 9 页、通栏 6 页、混合 2 页、自带顶栏 4 页；标题左边线从 200 到 421px 不等，页内三条左边线最多差 23px |
| 2 | 框套框 | 二层及以上的框：余额变动 63、债券分析 37、产品分类 35、团队绩效 28 |
| 3 | 粗体过量 | 首屏粗体字占比最高 69%（风险张量），多数页 40–64%；仍有 700 字重（发布展示 10%） |
| 4 | 颜色与标签噪声 | 强调色元素最多 75（组合）；彩色标签最多 46（团队绩效）；8 页挂常态徽标；12 页有装饰阴影或渐变 |
| 5 | 小字与表格不统一 | 11px 字符占比最高 86%（余额变动）；表头 4 种样式，行高 24–69px，单元格 5 种字号；未用等宽数字的数字最多 62 个（总账） |

另有：组合页“模拟数据/MOCK”出现 25 次；发布展示页有 5 个全大写英文眉标；市场总览的 MOCK 横幅遮挡导航文字。

21 页的 JS 错误均为 0，横向溢出均为 0，稳定性不是问题。逐页数字见执行方案附录 A。

## 3. 目标与成功指标

全站看起来是同一个专业金融工作台：一种骨架；层级靠字号与留白；数字能对齐比较；颜色只表达语义；状态清楚但不抢戏。

| 指标 | 基线（最差页） | 目标（每页） |
|---|---|---|
| 骨架形态 | 4 种 | 1 种；自带顶部的 4 页按 DESIGN §5.3 对齐 |
| 页内左边线极差 | 23px | ≤1px |
| ≥600 字重的字符占比 | 首屏 69% | 首屏 ≤22%，全页 ≤15%；700 及以上为 0 |
| 二层及以上的框 | 63 | ≤4，三层及以上为 0 |
| 11px 字符占比 | 86% | ≤15% |
| 强调色元素 | 75 | ≤15 |
| 彩色标签 | 46 | ≤4 |
| 未用等宽数字的数字 | 62 | 0 |
| 常态徽标（已就绪/已接入/已同步） | 8 页 | 0 |
| 演示/模拟提示 | 25 处 | ≤2 |
| 装饰阴影与渐变 | 12 页 | 白名单外为 0 |
| 业务回归 | — | 0：数值、口径、接口、权限、流程不变，相关测试通过 |
| 目视复核 | — | 每页通过三项目视检查与五问；样板页经用户确认 |

门槛的正式定义在 DESIGN §10.1；本表只是基线到目标的对照。

## 4. 非目标

- 不改业务逻辑、指标含义与数据口径、接口、权限和关键操作流程。
- 不换框架与组件库（React、Vite、AntD、ag-grid、ECharts 保留），不动数据层。
- 不新增主题，不做浅色方案；IB 存量按 DESIGN §2.4 处理。
- 不改 DESIGN §9 与页面规则锁定的区块顺序；经营日报首页的字号和留白不动，只换数字字体（D-D）。
- 不实现桌面客户端，只做预备（FR-7）。
- 不做业务数据对账，另行安排。

## 5. 用户与场景

- **用户**：投资、交易、风控和经营管理人员。多用 Windows，在 1440 级显示器或笔记本（最小窗口 1280×720）上长时间使用。
- **场景**：晨会前扫读经营结论；盘中看持仓、风险和市场；按口径下钻核对明细；导出与汇报。
- **审美诉求**：
  - 一眼找到结论；
  - 数字能直接比较；
  - 异常不被装饰淹没；
  - 切换页面不需要重新适应。

## 6. 需求

### FR-1 统一页面骨架（P0）· DESIGN §5.3

- 所有带壳层的工作台路由统一为“通栏终端条 + 无框主区”，删除浮框分支与按路由的外壳补丁。
- 新增 `--moss-page-gutter`，面包屑、子导航、页面标题和一级区块共用一条左边线。
- 页面结构按 §5.3 的顺序，优先用 page-v2 原语。
- 容器深度不超过 1；KPI 组是一条 KPI 带，不是一排卡片。
- 自带顶部的 4 页保留各自结构，只对齐顶栏指标。
- **验收**：骨架、左边线、容器三项门槛通过；9 个浮框页提供前后截图。

### FR-2 字体与数字（P0）· DESIGN §3

- 随包自托管 Noto Sans SC，提供 400/500/600 三档字重（可用可变字重版）；按 unicode-range 分片、`font-display: swap`，回退字体做度量对齐；系统字体作回退。
- 只用六档字号；字重只用 400/500/600，600 只给标题、KPI 主值和合计行；全局 `strong`/`b` 与按钮取 500。
- `body` 级启用 `tabular-nums`，数字列右对齐；业务数字不用等宽代码字体，首页也一样（D-D）。
- **验收**：
  - 字重、字号、数字三项门槛通过；
  - 字体加载前后没有明显的文字跳动；
  - 报告首屏实际加载的字体体积，超过 2MB 时先与用户确认。

### FR-3 颜色、装饰与状态降噪（P0）· DESIGN §4.2、§6

- 强调色只用于交互与当前位置；语义色只用于方向和异常。
- 彩色标签每页不超过 4 个，统一用 `StatusPill`；表格内状态用彩色文字或圆点。
- 删除白名单以外的阴影、渐变和发光。
- 删除常态徽标；演示/模拟提示每页不超过 2 处；修复市场总览 MOCK 横幅遮挡导航。
- **验收**：强调与标签、状态文案、装饰三项门槛通过；涨、跌、警示的颜色含义不变（抽查 `tone.ts` 的消费点）。

### FR-4 数据组件统一（P0）· DESIGN §5.4

- **表格**：DataTable、ag-grid 和页面手写表格共用 `--moss-table-*` 变量；行高 32，紧凑档 28；不改 `density.tableRowNormal`，它驱动 36px 的控件高度。
- **KPI 带、控件与按钮、导航、图表、空/加载/错误态**：按 §5.4。
- 视觉降噪 PRD 方向 A 的 KPI 迷你趋势线可以保留，前提是它表达数据，且不带来卡片化或阴影。
- **验收**：表格与控件门槛通过；`controls.mjs` 无违规。

### FR-5 样式架构收口（P1）· DESIGN §10.2

- 外壳由路由元信息 `layout` 驱动，不再按路由名加修饰类。
- 设计变量单一来源：一份 TS 定义生成 CSS 变量、AntD、ECharts 与 ag-grid 主题。
- 页面 CSS 只管布局；一个角色一套组件，例如 KPI 从 7 套收敛为 1 套。
- 审计以下四类违规并设存量基线，只降不升：原始色值、字号阶以外的字号、`!important`、按页面写的 `:has()`。
- **验收**：
  - 单一来源改造前后，各路由解析出的变量值逐项一致；
  - P4 结束时，外壳与全局样式层中按页面写的 `:has()` 补丁为 0，`!important` 只剩登记过的第三方覆盖；
  - 页面层的降幅写入报告。

### FR-6 审美合规检查工具（P0，最先做）· DESIGN §10.1

- 把 `.tmp/visual-audit-20261002/aesthetic-audit.mjs` 提升为 `frontend/scripts/visual-compliance-audit.mjs`。
- 1440×900 检查全部项，1280×720 复查溢出、截断、左边线和控件。
- 门槛与例外放在 `frontend/scripts/visual-compliance.thresholds.json`，例外须写明路由、原因和批准人。
- 违规时输出选择器清单，超过门槛时退出码非 0。
- 登记到 frontend/AGENTS.md 的证据工具。
- **验收**：在 21 页上复现执行方案附录 A 的基线；修正已知误报，即应用根节点的底色不计为框。

### FR-7 桌面客户端预备（P1）· DESIGN §10.3

- **运行时配置**：API 地址、数据模式改为启动时读取，由网页部署或客户端注入；`VITE_API_BASE_URL` 的三处读取收成一处，构建期变量保留为默认值。
- **平台服务**：导出/下载、本地存储、打印、剪贴板、打开外链统一走一个 `platform` 服务；网页版保持现有行为。
- **路由**：保留 `createBrowserRouter`，支持配置 `basename`；深链接刷新可用。
- **标题栏预留**：顶部终端条留出拖拽区和窗口按钮的位置。
- **长时间运行**：路由切换时销毁图表与表格实例、停止轮询。
- **窗口**：最小 1280×720；抽查 Windows 125%/150% 缩放。
- **验收**：
  - 网页行为不变，包括导出、本地偏好和深链接刷新；
  - 连续切换 50 次路由后，内存不持续增长；
  - Tier 2–3 测试与 typecheck 通过。
- 客户端技术选型（Electron 或 Tauri）以及原生菜单、托盘、自动更新、凭据存储，等真正开做时再定（见执行方案 §8）。

## 7. 验收

- **自动**：全部路由通过 DESIGN §10.1 门槛；例外均已登记理由和批准人。
- **目视**：
  - 同视口、同数据的前后截图；
  - 21 页首屏缩略图墙，改前、改后各一张；
  - 每页做三项目视检查（眯眼、灰度、与样板页并排）并回答五问（执行方案 §5）。
- **测试**：按 frontend/AGENTS.md 分级验证，并跑 typecheck 与 `debt:audit`。断言旧字号、字重或类名的测试，改断言，不删断言。
- **业务**：走查关键操作（筛选、切换、下钻、导出），结果不变。
- **用户验收点**：
  - P1 样板页 `/ledger-pnl`；
  - P4 全站缩略图墙；
  - 发布到 5888 前须经用户确认。

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| 外壳改动波及 9 个浮框页 | P1 只在样板页上经现有路由分支生效；P2 全量切换后，在三页上各检查三种宽度；单独提交，可回滚 |
| 删除 `:has()` 和 `!important` 引发连锁变化 | 分批进行，每批前后都跑探针和截图；审计基线只降不升 |
| 测试断言了旧字号或旧类名 | 按新规则改断言，不删断言 |
| 自托管中文字体的体积与替换跳动 | unicode-range 分片、swap、回退字体度量对齐；报告首屏字体体积 |
| mock 与真实数据观感不同 | mock 验收后，在 5888 真实数据入口只读抽查长名称、大数值和空值 |
| 多人并发修改 | 不用 stash、checkout、reset；改前看 diff；有冲突先报告 |
| 锁定页面 | 只改呈现层，不动区块顺序；首页字号不动 |
| macOS 与 Safari 内核未验证 | 目前以 Windows 上的 Chromium 为准；客户端若选 Tauri，再做一轮 WebKit 回归 |
| 探针是启发式统计，会有误报 | 以截图核实，确属合理的登记为例外，不放宽门槛 |

## 10. 依赖与约束

- **规则**：DESIGN.md、frontend/AGENTS.md、docs/frontend-layout-contract.md、docs/frontend-design-page-rules.md。
- **环境**：见执行方案 §7。要点包括：中文文件用 Node fs 读写，保持 UTF-8 无 BOM；不重启常驻 dev server；vitest 与 Playwright 不并发运行。
- **字体授权**：Noto Sans SC 采用 SIL OFL 1.1，可商用，可随软件分发；随包附上许可文件。
