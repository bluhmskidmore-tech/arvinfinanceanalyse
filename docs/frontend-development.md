# 前端开发工作流

源码开发默认使用 `http://127.0.0.1:5890`。`5888` 按运行控制器选择开发模式或固定验收构建；当它处于 `accepted` 模式时，修改源码不会让该入口热更新。检查改动前先确认浏览器地址和启动终端显示的数据模式。

## 启动源码开发

在 Windows PowerShell 中运行：

```powershell
Set-Location F:\MOSS-V3\frontend
npm run dev:source
```

此命令复用现有维护守卫，默认连接 `http://127.0.0.1:7888` API，默认使用真实数据。它不切换固定验收包，不启动后端，也不改变权限。依赖缺失时按提示安装。默认端口为 `5890`，占用时直接报错；可用 `npm run dev:source -- -Port 5891` 显式指定其他端口，保留的 `5888` 和 `5889` 不可用于该入口。

仅调整布局或检查示例状态时，可在同一个 PowerShell 终端明确选择 mock 数据：

```powershell
$env:VITE_DATA_SOURCE = "mock"
npm run dev:source
```

真实数据联调前把 `VITE_DATA_SOURCE` 设为 `real` 并重新启动。已有 `MOSS_VITE_API_PROXY` 会被保留，启动输出会显示实际代理地址。mock 检查不覆盖真实接口、发布版本握手或业务对账。

## 按改动选择检查

按 [frontend/AGENTS.md](../frontend/AGENTS.md) 的分级先运行相关页面测试。纯样式改动检查受影响布局、断点和可见状态；交互或数据读取改动检查对应组件或客户端及其直接调用方。普通前端代码改动仍需 lint 和 typecheck。

```powershell
npm run test -- <相关测试文件>
npm run lint
npm run typecheck
npm run debt:audit:frontend
```

`debt:audit:frontend` 是显式缩小范围的本地反馈：检查前端债务、视觉 token、字号、分节编号和 CSS 变量，不检查受保护的非前端大文件，也不运行全仓编码审计。它通过不能表述为全仓通过。完成相关开发后仍执行 `npm run debt:audit`；该默认命令及既有 CI 全量门禁保留。跨模块失败应记录具体文件和原因，不提高基线来消除失败。

## 小批次修改与验收

开始一个任务时记录本次拥有的文件、已有改动和最小验收范围。多人或多个代理并行时按文件划分职责，汇合后检查页面与组件、客户端与调用方的连接处。不要把工作区全部未提交内容归为本次修改，也不要仅凭 HEAD 相同认定源码相同。

页面拆分沿用现有 hooks、展示模型和组件。先抽出一个有独立职责的区域，保留 DOM、交互和数据语义，再用相关测试验证。样式调整应明确共享壳、页面和组件各自负责的布局范围，不继续依赖追加 `!important` 掩盖覆盖关系。

开发入口通过后，按授权生成候选构建并验收；更新固定验收构建另走已有发布流程。声称 `5888` 已生效时，必须核对该地址实际返回的构建及相关行为，其他端口通过不能替代这一证据。
