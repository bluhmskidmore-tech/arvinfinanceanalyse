# 市场总览数据与联动要求

本文件补充 Figma 施工规格 v1.4，覆盖 `/market-overview`。资金与利率摘要在首屏呈现，宏观、重点事件和组合情景摘要在首页常显。产品应先保证所需指标、图表和分析流程完整，再通过数据更新与核验恢复可用性。当前数据故障不能成为删功能或折叠全部摘要的依据。本次记录需求与实施落点，没有运行采集、回填、风险重算或修改生产接口。阅读顺序、来源条件和返回规则见 [市场总览阅读与联动约定](market-overview-interaction-contract.md)。

[主稿](https://www.figma.com/design/tlX0REVKGYO4v5rU6yXJoh?node-id=20-118) 展示市场观察可读、评分与信号待核验的分区状态；[待更新画面](https://www.figma.com/design/tlX0REVKGYO4v5rU6yXJoh?node-id=33-266) 展示观察也受限的状态。数值和核验状态均为设计样本。

## 当前证据与目标能力

2026-09-08 对本机接口的只读核对显示：宏观行情接口返回 133 条序列，市场接口返回的 78 条均包含在其中；首页快照含 8 项行情、资金观察、三个国债期限、四项宏观脉冲、新闻和危机评分历史。新闻接口报告 4,687 条，快照取最近 500 条；危机评分含 60 期历史，当前评分受依赖核验限制。这是当时的接口返回范围，不是全库清单或未来覆盖上限。

许多行情日期停在 2026-09-04，部分序列更早。快照报告最近刷新因调度配置问题未完成，资金与曲线判断受限。单条序列 `quality_flag=ok` 不能单独证明数据及时、比较日期一致或分析依赖齐备。政策有效期与精确 DR007 的缺口也不能只靠重新请求同一接口解决。

### 行情、曲线与资金

行情保留八项业务入口，首屏突出四项，其他项可直接进入全部行情。每项必须包含指标身份、值、单位、变化口径、观察日、比较日、来源以及代理或回退标识。数值和日期应由同一条记录生成，零值与缺失分别展示。

国债主图回答“哪个期限变化、幅度多大、期限差是否变化”。首屏用 2Y、5Y、10Y；专题保留已定义的其他国债与国开期限。变化采用后端 `change_bp`，利差采用 `spreads.value_bp / previous_value_bp / change_bp`。同一来源及同一比较期间通过核验后，才描述这三个节点的共同变化，不能把三个节点等同于完整曲线。

曲线的数值核对关系是：以百分数表示的收益率相减后乘 100 得到 bp；10Y−2Y 利差与其跨期变化分别核对。已有计算位于 `market_observation_service.py`。前端只格式化与选择展示；新增诊断措辞应补到后端规则并保留对应证据，不能在前端另算正式指标。

资金区保留 DR007 目标指标、现有 FDR007 代理、SHIBOR 3M 与政策参考的业务关系。取得精确 DR007 是数据补齐要求，不因现有代理可画图而取消。资金价格变化可以作为资金条件的观察，但不能直接等同本行融资成本变化。政策基准需核验来源、有效起止日期及口径，不能把最后一次操作日当作完整有效区间。

主图点击期限后，依据视图定位相同期限定点及比较记录；关键利率视图同步选中该序列，保留观察窗口。点击资金读数进入资金依据，不打开国债依据。前后端必须共享序列 ID、观察日与比较日，不能靠显示名称猜测关联。

### 跨资产、宏观与事件

跨资产条图保留每项独立比较日期。对原油、铜、股票、汇率等指标做“同一日共同变化”分析前，必须增加共同有效观察窗口；没有共同窗口时仍展示各项原始变动，不能把它们拼成统一日排名。观察指数的归一化基准、收益口径与缺口处理沿用已验证模型，并在专题说明。

宏观区保留 CPI、PPI、PMI、社融等已定义指标及专题能力。页面同时解释指标期和发布日期；同比增速的变化使用百分点，PMI 变化使用点。宏观数据按发布周期核对，不能按日行情的日期标准认定过期。缺少后续发布的数据，应补齐发布记录及历史修订版本，而不是移除该指标。

首页四项沿用正式页面契约已定义的 `macro_pulse` 身份：CPI 同比 `M0000612`（%）、PPI 同比 `M0001227`（%）、制造业 PMI `M0017126`（index）、社融存量同比 `M5525763`（%）。CPI、PPI 和社融的变化单位为百分点，PMI 为点，不能把社融增量替代存量同比。页面展示最新值、较前一期变化、指标期、发布日期和简短观察。已定义的序列身份不再列为待设计项；实际响应映射、发布日期覆盖及来源匹配仍逐项核对，缺口记为 PENDING。观察摘要只能使用后端允许的结论；若没有对应规则和证据，应补充后端契约，不能由前端照抄合成样本文案。

事件区联动所选主题和时间范围，展示原文来源、事件时间、接收时间与影响对象。新闻数量和主题密度描述样本分布，不代表利好利空强度；只有日期的记录不能进入精确小时判断。既有时间筛选是接收时间筛选；若要按事件发生时间联动，须先补齐字段与接口契约，不能混用两种日期。

首页最多显示三条事件摘要，首版沿用所选主题和接收区间，在去重后按接收时间倒序取记录，不新增未经定义的“重要性”分数。每条直接呈现主题、标题、关注对象、来源及双时间，“更多事件”进入已有新闻页。设计中的流动性、增长与融资、海外与商品是展示样本，不代表后端已经按这三个主题生成归因。去重键、主题键、影响对象及双时间字段的最终映射为 PENDING；缺少事件发生时间时明确显示未提供，不能拿接收时间代填。

“可能影响”描述经业务规则允许的传导机制，“关联核对”提供需要共同查看的指标与事件。共同涨跌不能直接写成因果。定量关联分析若缺少共同样本、方法和样本量字段，应作为待补分析能力记录，不能用推测性文字假装已完成。

### 危机评分、策略与组合情景

危机评分保留当前值、历史、组成项和依赖状态。输入更新并核验后恢复当前评分；当前值不可用时，历史仍可按明确历史日期展示。不能拿最后一个历史评分代替当前值。策略专题保留期间收益、超额收益和回撤，明确影子组合身份、基准及统计区间，避免与本行实际业绩混在一起。

组合情景当前实现支持固定平行上行 10 bp，使用监管 DV01，指标 ID 为 `MTR-RSK-001R`。接口按 `-regulatory_dv01 * shock_bp` 返回估算影响，单位为元；生产前端读取 `estimated_impact`，不自行使用首页某个期限的变化重算。

进入情景时传递曲线观察日，再由既有风险日期接口选择可用风险日。只有响应实际风险日等于所选日、覆盖完整、来源无回退、金额允许展示、权限有效时才显示结果。选择历史风险日后，标题明确为历史持仓情景；403 时隐藏当前与缓存金额。

组合区在首页始终显示。首次访问展示固定 +10 bp 条件和“加载组合情景”，由用户操作触发日期与风险查询；读取成功后在原位置展示实际风险日、后端估算影响及覆盖计数，计算依据继续使用详情层。首页的常显要求不授权自动读取私人持仓，也不允许用缓存结果绕过当次权限。页面刷新后能否复用已加载结果，继续服从既有风险日期和权限校验。

正常情景必须展示冲击、估算影响、纳入持仓数，以及总量、按口径排除数和风险输入缺失数。覆盖完整指规则范围内输入完整，不要求总持仓全部纳入。到期日或风险输入缺失应进入指定日数据补齐与重算任务，不能永久取消组合影响入口。真实行情归因、任意期限冲击及账户拆分尚不属于当前首页已支持能力；如需扩展，单独补充计算契约，保留需求记录。

## 更新要求与恢复流程

| 数据类别 | 时效核对依据 | 更新后的必要结果 |
| --- | --- | --- |
| 日行情、曲线、资金 | 交易日历、发布窗口、市场时区 | 预期观察日及比较期齐备 |
| 月度或季度宏观 | 指标期、发布日、修订版本 | 应发布期间已覆盖 |
| 政策基准 | 有效区间、来源及口径 | 有效期覆盖观察日 |
| 新闻 | 接收批次、事件时间、去重键 | 新事件及时间精度可追溯 |
| 危机评分、影子策略 | 所有必要输入及计算版本 | 依赖核验后重算结果 |
| 持仓与风险 | 明确报告日及监管计算范围 | 实际风险日和覆盖核验通过 |

每个指标还需落定预期发布日历、允许延迟和历史修订策略。当前存在 `frequency=unknown` 的序列，逐序列发布规则为 PENDING，不能凭空设定统一“超过一天即陈旧”。这些规则缺口进入数据目录完善任务。

页面现有“刷新数据”在 `MarketHomePage.tsx` 中调用 `refreshChoiceMacro(30)`，启动既有宏观刷新并轮询 run_id，结束后重读快照和已加载区块。必须清楚展示该入口的范围以及 partial、degraded、失败结果；重读了新闻或策略接口，不代表本次已经重新采集新闻或重算策略。若仅重新请求页面数据，文案不得表示源数据已更新。

完整市场更新通过数据中心 `POST /api/data-updates/market` 请求已注册的市场任务；指定报告日的余额、持仓和风险沿用财务更新流程。具体执行约定见 `docs/data_update_center.md`。设计不把两个不同范围的更新包装成一个保证全部成功的按钮，也不允许用户界面直接运行脚本。

更新开始后保留上次有效观察及日期，显示正在更新的范围。失败时显示原因和既有恢复入口；成功后核对执行回执、实际结果日期、必需输入和区块使用资格，再恢复相应结论。只有收到各区块明确的核验结果才恢复，不能因刷新请求已提交或进度结束就把状态涂绿。

## 实施与验收要求

先完成正常状态和数据受限状态的页面编排，再接回逐模块字段、依据和联动；同步把采集配置、精确 DR007、政策有效期、历史覆盖和风险输入等缺口列成有明确日期及范围的更新任务。不得用当前快照缺失把设计模块直接删掉。所需的新字段或方法另标 PENDING，不把方案中的目标能力写成已经存在。

验收需分别覆盖正常数据、过期数据、更新中、更新失败、部分缺失、完整空数据和无权限。正常状态能从观察进入依据和情景；异常状态保留相同模块及入口，并说明受影响范围。一个模块异常时，不隐藏其他有效观察，也不绕过现有后端依赖核验来放行结论。

常显范围另行验收：不点击折叠控件即可读到四项宏观摘要、最多三条事件和组合情景状态；缺失项仍占对应位置。手机采用纵向阅读，读数不裁切，新增操作区至少 44px。宏观详情、更多事件及组合依据分别到达对应功能；十二项专题和全部行情保留原入口。

合成样本核对：曲线 2Y/5Y/10Y 分别变动 -0.50/-0.50/-1.00 bp，10Y−2Y 利差为 43.00 bp、较前期收窄 0.50 bp；资金历史 null 不连线；政策有效但只有代理时偏离仍为空；组合固定 +10 bp 对应 -1,250,000.00 元，持仓计数 120=100+20，缺失 0 项。样本仅用于设计和测试，不写入生产业务表。

本次代码依据为 `useMarketHomeQueries.ts`、`marketFinancialChartsModel.ts`、`MarketHomePage.tsx`、`MarketPortfolioScenarioPanel.tsx`、`market_overview.py`、`market_observation_service.py` 及 `risk_scenario_stress_service.py`。Figma 连线和导出检查不替代生产环境的权限、网络、键盘与业务回归验收。

首页继续消费既有快照，不因常显而新增全量详情请求。评分详情按需使用 `GET /ui/macro/toolkit/analysis?detail=full&history_limit=60`，按 key=`crisis_score_cn` 定位能力；不能依赖能力数组下标。详情响应的实际报告日与首页来源日分别显示，不能把最新完整分析当成历史回放。该接口已有，首页详情的查询启用与错误处理仍须实施。

`current_available=false` 或发布依赖阻断时，不展示当前 score/regime/percentile；raw result 中有值也不能回填。风险触发以 `risk_gate.eligible && risk_gate.triggered` 为准，资格不足不能写成“未触发所以安全”。历史点按各自 data_status、available_component_count、component_count、available_weight 保留质量；20/60 期以实际 window_points 和起止日期呈现，不足期数不补点。分位是历史排名，分位变化单位为百分点。

五项原始量须按身份与来源单位映射：股票、汇率、商品项为年化实现波动（%）；信用和流动性差值在两条百分比利率输入已核验时为百分点。当前 components 无独立 unit 字段，不能对未知身份或未确认单位自动套用格式。标准化值与评分均无量纲，原始值、显示精度与配置权重分列，不在前端重建评分或贡献。来源 `CA.DR007` 必须继续显示 FDR007 代理身份。

商品影子贡献已有后端字段，直接展示，不按六项平均分摊。现有方法每项权重为 0.05，先四舍五入单项贡献后汇总差额，再与原始模型试算相加；仅用于核对设计样本，不将计算迁至前端。准入重叠样本阈值 20、危机样本阈值 5、相关性阈值 0.20 均读取对应返回值，不能固定写死 UI。危机样本不足属于暂不纳入，相关性偏弱属于继续观察。空审批清单与缺失审批材料分别呈现，完整返回的 copy_text 保留且不产生审批提交。

信号不可用时保留模块和后端原因，不补造方向；可用时按实际有效卡片数量呈现 title、stance、score 和 evidence，运维卡不参与方向。新闻同向、冲突、待复核及候选情景是不同维度，可能重叠，不合计为新闻总数；接口失败的占位零不能当成有效零。

`risk-fixture-v1.4.json` 为独立合成数据。主稿的受限状态不表示生产已经更新；可用状态另假设精确 DR007、政策回执和商品历史均已恢复。六个商品候选采用样本充足、相关性偏弱的继续观察示例，影子贡献合计 +0.050，与影子评分 −0.55 一致。
