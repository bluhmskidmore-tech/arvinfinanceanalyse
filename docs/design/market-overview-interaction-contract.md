# 市场总览阅读与联动约定 v1.4

本文件将 `/market-overview` 的全系统设计目标落到阅读次序、常显范围、下钻条件和返回行为。版本日期为 2026-09-09，状态为设计已定义、生产待实施。Figma 使用合成样本；这里规定目标行为，不宣称现有页面已经承接新参数。

v1.4 已补齐 [业务覆盖检查](market-overview-business-coverage-review.md) 确认的缺口，评分、信号与核验事项常显，商品研究有实际下钻画面。生产接线和浏览器验收仍待实施。

## 首页要回答的问题

市场首页先回答资金与国债利率在各自观察期间发生了什么变化，再说明可以使用哪些证据、有哪些解释限制，以及需要怎样核对持仓影响。它是市场环境的入口，不承担经营日报的整体经营判断，也不取代风险工作台或正式损益归因。

首屏按标题与工具、本期市场观察、章节导航、四项核心行情、国债曲线与影响核对排列。市场观察直接读取 `funding_observation.summary` 和 `rates_observation.summary`，各自保留观察日及比较日。前端不把两个摘要投票为市场方向，也不推导买卖指令；任一摘要不具备判断资格时，该摘要展示后端原因和恢复入口，保留允许使用的带日期事实。

右侧影响核对分别说明估值、融资成本和宏观背景。利率变化对固定利率债的作用属于条件性机制；资金代理不代表本行融资成本；宏观指标与新闻提供背景，不能只因同步变化就宣称因果。生产只能使用后端允许的 interpretation 与证据。设计中新增的精确措辞若尚无对应规则，必须补齐后端契约，不能照抄样本文字。

## 默认可见与工作台分工

| 内容 | 首页默认呈现 | 深入阅读 |
| --- | --- | --- |
| 市场观察 | 资金摘要、利率摘要及各自日期 | 核验原因与恢复项 |
| 行情与图表 | 四项行情、国债曲线、资金图、跨资产图 | 关键利率切换、十二项专题、全部行情 |
| 风险观察 | Crisis 当前状态、60 期历史、20/60 期变化、市场信号与核验事项 | 五项组成、七条输入、商品研究与新闻复核 |
| 宏观背景 | CPI、PPI、PMI、社融四项及日期 | 指标依据、宏观观察 |
| 重点事件 | 最多三条、主题、关注对象、来源和双时间 | 当前范围、新闻事件 |
| 组合利率情景 | 固定冲击与未加载或已加载状态 | 计算依据、指定风险日详情 |

常显指无需打开折叠控件即可阅读，不要求把完整页面压进一个视口。已有四张首页图表的能力保留，资金和关键利率使用同区切换。评分的近 60 期历史在首页常显，完整历史、明细表、技术溯源和十二项专题可下钻；策略专题继续保留，不把供应商覆盖或能力状态当作市场方向证据。

组合摘要首次访问仅显示固定平行上行 10 bp 条件和加载入口。用户操作后才查询风险日期和情景，结果使用后端 `estimated_impact`。它与实际行情冲击及当日损益分开，不能拿首页 10Y 变动代入固定情景。Figma 正常主稿展示用户已加载后的样本，独立未加载状态仍是首次访问的实施基准。

## 下钻条件与返回

首页内查看依据使用抽屉，手机使用全屏覆盖层。关闭按钮、遮罩和 Escape 回到原位置，焦点回到触发控件；关闭不清除资金/关键利率选择、当前序列、专题展开、新闻条件或仍有权限使用的情景选择。

| 入口 | 必须保留的业务条件 | 目标 |
| --- | --- | --- |
| 曲线依据 | 序列身份、期限、观察日、比较日 | 当前期限的证据记录 |
| 资金依据 | 资金序列、代理身份、观察窗口 | 对应资金证据 |
| 宏观详情 | 指标身份、指标期、发布日期 | 宏观依据覆盖层 |
| 更多事件 | 真实主题代码、接收起止值 | 事件范围覆盖层 |
| 查看组合情景 | 曲线观察日、用户选择的风险日 | 固定 +10 bp 情景 |
| 风险详情 | 已核验的实际风险日 | `/risk-tensor?report_date=…` |

Figma v1.3 的宏观和事件覆盖层显示所带条件，并通过 CLOSE 回到原首页。其“进入宏观观察”和“进入新闻事件”仍打开现有页面入口；跨页参数承接属于下面定义的实施工作，当前生产和 Figma 外链均未证明该能力已实现。

跨页导航采用现有路由，不新增全局状态框架。进入前保存市场页的控件状态与返回锚点；目标页给出“来自市场总览”的业务条件和返回入口。返回锚点限市场页已定义章节，不能执行任意外部地址。原页状态可通过现有路由 state 或页面现有状态方式保留，具体接法在实施前检查已有模式。

以下是待实现的 URL 接收约定，不是已经可用的链接。`origin=market-overview` 与 `return_section` 表示来源和返回位置；`return_section` 只接受 `market`、`risk`、`macro`、`events`、`scenario`。受保护的持仓数据、权限状态、情景金额不进入 URL。

| 目标 | URL 字段 | 对目标查询的作用 |
| --- | --- | --- |
| 宏观观察 | `indicator_id`、`indicator_period`、`published_at` | 定位已存在的指标证据 |
| 宏观观察 | `market_observation_date` | 仅显示来源观察日 |
| 新闻事件 | `topic_code`、`received_from`、`received_to` | 传给既有事件查询参数 |
| 风险详情 | `report_date` | 使用现有风险日期选择逻辑 |

宏观观察当前读取最新分析，不支持通过来源行情日回放历史。目标页应将来源条件与实际读取日期分别显示；所选历史指标无法定位时明确显示该差异，不能把最新分析伪装成截至来源日的历史结论。未选具体指标时省略指标字段；四项已定义序列身份沿用正式页面契约。

新闻主题必须使用记录中的 `topic_code`，不能把“流动性”等设计样本标签猜成查询代码。全部主题时省略该字段。接收时间值沿用源查询的规范化值及既有接口边界，不重新解释为事件时间或擅自转换时区。目标页解析并校验条件后，在 query key 和 `getChoiceNewsEvents` 参数中同时保留它们，改变筛选后重置分页。无效条件必须可见，不能悄悄显示全量结果。

风险日沿用现有 `report_date`。优先核对与曲线观察日相同的可用风险日；缺少同日数据时让用户选择可用历史日，并显示历史持仓情景。实际响应日期、覆盖和权限不合格时不显示金额。当前可核验范围是接口定义的监管风险持仓范围，不能从这版设计推导出尚未存在的任意账户或组合筛选能力。

## 实施与验收次序

先按本稿调整市场页现有布局并接回已有快照摘要，确认正常、待核验、缺失和未加载状态；再补新闻和宏观目标页的最小条件接收及返回，复用既有新闻接口与风险报告日逻辑。正式计算、数据库和全局状态基础设施不在本轮设计范围。

完成的判据是读者无需点击即可知道市场变化及其限制，能从对应摘要打开同一条件下的证据，再回到原处；所有日期、单位、代理和权限边界仍正确。验收分别记录 Figma 节点与截图、生产截图对照、来源条件与返回行为、数据/权限回归。图稿正确或连线存在不等于生产验收通过。

## v1.4 风险观察的联动

风险区常显在资金/跨资产之后、宏观/组合之前。章节“风险观察”滚动到同一页面的该区；手机两行导航保留全部五个入口。当前评分、历史、信号与待核验事项独立呈现，不把一个分区的失败扩大为整页不可读。

“评分依据”和 P2 核验进入同一报告上下文的 Crisis 详情，保留首页图表选择和滚动位置；其中“商品扩展与影子分析”进入商品详情，返回先回到评分依据，再回首页。“查看信号依据”打开方向可用性与证据；P1 打开新闻比较和人工复核说明；P0 与恢复入口前往既有 `/macro-toolkit`，不在原型中假装刷新已执行。

商品详情的覆盖、影子分析、准入与审批采用同一滚动容器内的章节定位；审批材料只读。新增 54 个首页动作已连接明确目标，八个详情具有返回行为，核验与专题目录另有入口。Figma 展示静态样本和连线，真实请求、Escape、焦点锁定、恢复选择与外链返回仍须浏览器验收。

历史图桌面悬浮、手机点选展示 `103:1925` 的点提示：日期、原始评分精度、历史分位、组成项覆盖及数据质量。提示不改变当前评分。真实选择的点来自原序列，不以设计末点响应全部位置；当前 Figma 只提供提示样式，不伪造动态查询。

跨页来源约定新增受控返回位置 `risk`。评分报告日作为来源提示，目标完整分析仍显示自己的实际报告日；现有宏观页没有历史回放保证，参数接收属于实施任务。本次原型外链仅使用已存在的路由，不宣称新增筛选已可用。
