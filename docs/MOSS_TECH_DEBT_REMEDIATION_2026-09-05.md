首批应修复债务检查自身，再收紧已经下降的基线。现在 [视觉基线更新](/F:/MOSS-V3/scripts/audit_visual_tokens.mjs:220)、[编码基线更新](/F:/MOSS-V3/scripts/audit_encoding_integrity.mjs:98)、[序号基线更新](/F:/MOSS-V3/scripts/audit_section_numbering.mjs:120) 和 [CSS 变量基线更新](/F:/MOSS-V3/scripts/audit_undeclared_css_vars.mjs:160) 都存在直接用当前值覆盖基线的路径；后三项还把这种行为命名为 `--ratchet`。新增错误后执行这些命令，可能把错误记入允许值。应沿用现有前端审计器的比较思路，新增非零项或高于旧基线时拒绝写入，整体检查通过后才允许下调；保持编码损坏、无归属编号和未声明 CSS 变量的零上限。

同批补齐大文件防删检查。[必保路径](/F:/MOSS-V3/scripts/audit_frontend_debt.mjs:19) 只有 7 项，而 [登记清单](/F:/MOSS-V3/scripts/debt-baselines.json:23) 有 11 项，删除漏保护条目会使文件退出检查。常规审计、自检和测试都应核对完整集合。随后将所有已下降上限收紧到冻结实测值，并给高占用热点补文件级约束，避免一个文件减少抵消另一个文件新增。基线前后差异和复核证据随变更留存。

这批的验收必须证明检查能拦错：在隔离副本中把零基线对应的实测改成一，更新命令必须失败且基线字节不变；减少债务才允许下调。删除任一受保护文件条目，常规审计和自检都应失败。同样，在一个文件减少一处、另一个受保护文件增加一处时，后者不能被总量抵消。验收通过后再执行六项总审计，不能用“更新基线后全绿”作为修复证据。

后端也需要把观察检查变成有效的新增问题门禁。[CI 的 BLE001 步骤](/F:/MOSS-V3/.github/workflows/ci.yml:443) 使用 `|| true`，[mypy 任务](/F:/MOSS-V3/.github/workflows/ci.yml:447) 设置 `continue-on-error: true`，所以检查失败仍可继续。先在 CI 约定的 Python 3.11 和 mypy 1.20.1 环境复核既有基线，再让新增类型错误和未经审核的宽泛捕获阻止合并；合理的顶层捕获保留明确理由。现存问题按模块减少，不通过关闭规则或整体刷新基线消除报告。本轮没有用不同本机环境重刷 mypy 基线，也没有把 167 条 Ruff 发现写成 167 个已证实缺陷。

运行协同应紧接着处理，且必须先于下一次无人值守正式发布。现有 [正式任务锁](/F:/MOSS-V3/backend/app/tasks/formal_compute_runtime.py:79) 只串行写任务；[API 启动](/F:/MOSS-V3/scripts/dev-api.ps1:38)、[worker 启动](/F:/MOSS-V3/scripts/dev-worker.ps1:6)、[整套启动](/F:/MOSS-V3/scripts/dev-up.ps1:536) 和 [keepalive](/F:/MOSS-V3/scripts/dev-keepalive.ps1:555) 没有共同维护窗口。此次另一任务重启 API 并造成读锁碰撞，已经是实际证据。最小方案是在这些现有入口间建立与规范化数据库路径对应的维护状态和互斥检查，发布取得维护权后禁止重新拉起服务，等待正在执行的任务和读连接退出，再调用原物化任务。中断后保留持有者、阶段和恢复信息，不能单凭超时自动开放服务。

同时让恢复脚本区分源码开发模式和已验收构建模式。目前 5888 服务验收构建，而 [前端启动脚本](/F:/MOSS-V3/scripts/dev-frontend.ps1:45) 启动的是开发服务器，[keepalive 前端探针](/F:/MOSS-V3/scripts/dev-keepalive.ps1:73) 又检查源码路径。构建模式需要保存并复用产物目录、构建标识、real 数据源和代理目标，探针验证实际运行标识。两项运行整改均先在隔离端口、临时数据库和独立进程中演练：发布中启动 API 应被阻止，两个发布不能并行，恢复不能丢治理记录，不能误停其他工作目录进程，重启前后的构建哈希与代理目标必须一致。没有证据支持因此换数据库或重写框架。

输入和业务口径的缺口应与上述技术整改并行整理，但不能由开发人员猜定。已验收的 2026-07-31 截面中，127 个债券行和 1,590 个负债行缺到期日，相关流动性计算已排除这些行；1,617 个债券行缺明确付息频率，暂用年付息代理。这些是 [实际接口已经披露的限制](/F:/MOSS-V3/.codex-tmp/global-publish-2026-09-05/http-verification.json)，并非此次新增错误。先建立逐来源的缺失清单，从获授权的主数据或原始文件补齐并留存出处，不能补默认值后标记数据完整。正式落库仍走任务层，补齐后复核覆盖率、金额变化、来源与质量状态。

Campisi 范围、Cube 正式资格与可加集合、非月末 TTM、多版本权威和快照陈旧阈值，需要业务负责人确认。技术侧先把每一项整理成可判断的选项、金额影响及黄金样本，确认后再落契约和反例测试。首页治理待办来源未接入、持仓页黄金样本和指标契约待确认，也应纳入同一张责任清单。在依据补齐前继续保留限制，不能为了视觉上的“全绿”删除提示。

大文件拆分放在边界和基线稳定以后，一次只动一个业务流程。产品分类损益页同时编排多组查询、状态、转换和渲染，模型又集中场景、归因、回测和趋势；余额变动页还承担导出。因此先按可独立核对的展示区、查询编排或纯转换拆分，复用已有工具，正式金融公式继续留在后端。先固定 API、单位、报告日、空值和输出样本，完成符号影响分析，再修改；每批运行针对性测试、lint、typecheck 和真实页面核对，同时下调对应上限。把几千行搬进另一个模型文件，不计作偿还完成。

界面和性能债按实际使用路径处理。先消除影响阅读的过小字号、重复静态样式和密集版本信息，保留必要的质量披露。性能先保存代表性数据量和同一输入，测冷/热请求、并发、内存及延迟分布，再修改已证实热点；此次首页三个响应约 3.1 至 4.3 秒只是单次观测，不能写成生产 p95 或据此承诺提速比例。
