## 已有曲线与首次发布维护窗口

第二次请求在债券步骤运行约 31 分钟后自行失败，没有人工强停。错误指向正常 API 对活动 DuckDB 的读取。代码同时证明缺少当日曲线时会先逐日尝试供应商，之后才查询窗口内已有快照；目前没有分阶段日志，不能把全部耗时归为网络等待。

网页 Pro 已接受独立曲线恢复补充方案，尚未使用第三轮执行复核。请求必须明确携带所需日期基准、曲线类型、快照日期和来源、供应商、规则版本。全局流程仅向明确启用的恢复请求透传；债券任务按实际依赖重新选择快照，并在首次事实修改前检查既有 40 天窗口、血缘与点位规则。汇率与曲线选项彼此独立，默认行为不变。当前债券计算并不直接使用这些曲线，本项只保证准备依赖资格，不构成久期或 DV01 计算验收。

本次首次发布采用已授权的维护窗口：先通过全部合并验证并冻结源码、曲线清单，再暂时停止正常 API、worker 和监督进程，保留 5888、Redis 与 PostgreSQL。解除已有启动维护门后，仅恢复原数据中心计划任务，由既有请求服务提交一条关联第二次失败的新请求，仍通过原后台 drain 执行。执行期间 API 保持停止，避免活动库读取与写打开冲突。终态及 drain 退出均确认后恢复服务；发布证据有效才保留发布开关开启，否则恢复旧读取配置，原调度状态必须恢复。

维护窗口只用于隔离本次初始写入。即使发布和独立读取负载均通过，也不能据此宣布日常在线更新的活动数据库并发问题已经解决；后续须单独限定读写协调范围并验证，不能把包含网络等待的长任务锁直接扩展给所有读请求。

## 首轮核心修改

`financial_publication_enabled` 会切换详情页使用的日期、准备状态与 insights 读取。旧 `/pnl-by-business` 页面仍从普通日期目录选日，并向同一 insights 端点发出无 generation 请求。因此不能仅打开开关：当前发布未覆盖旧页选定日期时，该部分会报错。

首改限定旧损益主页的准备状态和 insights 查询块，复用详情页现有协议。普通日期目录和旧页其他损益请求保留；legacy 状态沿用原读取，发布协议下只有 ready 且有 generation 时读取固定版本。未发布、过期、切日期及迟到旧响应必须明确呈现，不显示此前缓存金额，不自动选择其他日期冒充所选日。

首轮最多五个实现上下文文件为 `PnlByBusinessPage.tsx`、其新的 publication 组件测试、`pnlClient.ts`、既有 `pnlClient.test.ts` 和作为模式参考的 `PnlByBusinessInsightsPage.tsx`，最多两次定向搜索。第一条证明命令为前端目录运行 `npm run test -- src/features/pnl/PnlByBusinessPage.publication.test.tsx src/api/pnlClient.test.ts`。随后按影响运行详情页定向测试、typecheck、lint 和 debt:audit。禁止改全局客户端、金融公式或把整个旧页移入另一套状态架构。

GitNexus HEAD 与索引记录相同，但未提交新符号可能漏报；已知路由挂载与共享消费者须用实际调用核对。旧页函数图谱影响为 LOW，不能把零图谱调用者当作没有实际消费者。共享运行入口若需要改动，须另做对应符号影响分析，提前说明高风险。

## 正常运行接线与发布准备

复用当前 worker、Redis、日常启动脚本、数据中心请求服务和发布协议，不再创建并行 broker、调度器或发布框架。核对 API、worker 和计划任务各自实际读取的配置与治理目录，显式选择已验证的 `bounded_v1` 资源配置。损益发布目录绑定正式数据来源并独立于余额目录；具体配置、父子进程归属与回退值在操作前记录。

已确认 API 和 worker 加载 `dev-env.ps1`，计划任务 `drain_data_updates.ps1` 没有加载，且现有日常启动未选择资源配置。正常 core_financial 已有同步页面准备与 CAS 发布，无需再造发布链路；但资源配置只会约束显式进入既有资源 scope 的执行，不能仅凭环境变量声称同步整链已经受限。该接线缺口须在首个前端证明通过后，沿已证实的入口作最小修复。

报告日先按来源预检、已有结果及依赖资格确定，以 2026-08-31 作为待核验候选，不将表中最大日期直接当作输入完整证明。先只读核验来源文件类型、日期、解析、既有任务、历史依赖与网络/锁条件。已存在且合格的结果优先复用；只有准备状态证明的依赖缺口才补算必要日期，并在执行前说明范围。

真实更新必须经数据中心的既有请求服务和后台执行链路。涉及损益使用 `core_financial`，不同时提交同日 `balance_daily`。完整更新中的产品损益目前可能处理历史月份，不能把单日请求描述为全链路增量或承诺固定完成时长。确定性坏文件只阻塞依赖它的日期，已完成步骤按既有能力核对，禁止为试错重复整链重算。

启动或停止正式进程前确认归属、活跃任务和写锁；需要维护窗口时复用已有控制入口，并在结束前恢复 API、worker、前端与原有调度。无待执行业务时不以强杀制造正式故障；故障能力沿用前一批冻结源码证据，新增接线仅补正常入口的消费和恢复证明。

## 构建切换和回退

先保存当前验收构建、manifest、前端选择状态及实际响应指纹。检查既有构建与选择流程能否限定目标路由；若必须发布整个前端构建，显式记录影响，并按现有守卫验证所需公共边界，不能把整个脏工作树描述为全部已审查。

新构建先在独立端口验证损益详情和旧主页的日期、固定代次、未覆盖状态及正常跳转，再用既有选择入口切换 5888。最终以 5888 返回的新构建身份和真实浏览器行为为准，不能以构建成功或临时服务器成功代替正式接入。

配置及前端回退不得回滚或覆盖已写正式事实，也不得重新启用失效发布。正常错误状态应明确展示；只有仍有资格的发布版本可以提供读取。保留原有计划任务和无关页面，不无声修改认证身份或访问权限。

## 完成条件

必须同时满足：旧主页共享请求具备正确日期与代次门禁；损益详情在实际 5888 上使用新构建和正式发布结果；正常启动的 worker 使用同一 broker 和治理目录，资源配置在真实任务中生效；既有更新请求产生数据中心可见回执，关闭浏览器不影响后台完成；读取的日期、版本、关键业务字段和来源资格一致。

正常读取继续采用已约定的接口 P95 不高于一秒和无锁错误标准，按指定负载验收，不将后台全财务更新套用此前特定冷准备的 120 秒门槛。未准备日期、失效版本和更新失败不得穿透读活动库或展示误导金额。配置和前端回退可执行，结束时服务健康、没有遗留试验进程或未披露的活跃任务。
