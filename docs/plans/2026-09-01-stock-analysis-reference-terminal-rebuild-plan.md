# `/stock-analysis` 参考稿驱动的机构研究终端重建方案

> 日期：2026-09-01\
> 路由：`/stock-analysis`\
> 当前页面标识：`GAP-STOCK-ANALYSIS-PAGE`\
> 当前业务边界：`observational_only`、`formal_use_allowed=false`\
> 文档性质：`2026-08-31-stock-strategy-cockpit-prd.md` 的第一阶段实施补充，不替代原 PRD\
> 固定范围：只重建股票研究页；不修改首页、组合子路由、全局壳层和 Nocturne/Fable 色系

## 一、结论

当前股票页只能作为结构草稿，不能继续靠间距、边框和卡片尺寸微调冒充参考稿成品。参考稿明显更强的原因，是它把候选筛选、价格验证、关键指标、研究结论、因子判断、事件证据、风险门槛、下一步动作和审计留痕组织成了一条连续的研究决策链；当前实现虽然栏宽接近，但内部仍是多个同权重卡片的拼装，价格图、核心结论和风险动作没有形成稳定主次。

本方案采用两条工作线。第一条立即使用仓库现有的 workbench、个股行情、K 线分析、候选历史和新闻事件合同，重建真正可用的研究终端；第二条单独补齐机构参与和因子表现序列等缺失合同。第一条完成后，页面的专业度和决策效率会发生明显变化；第二条完成后，才能补齐参考稿里目前没有数据支撑的金融可视化。任何阶段都不允许用静态演示数、前端推导或装饰图形填补合同缺口。

## 二、要解决的核心问题

页面必须首先回答一个问题：在同一个观察日和策略上下文中，哪只候选最值得继续复核，支持证据和失效条件是什么，下一步可以做什么。

当前页面的主要断点不是色系，而是以下四项。

| 断点 | 当前表现 | 目标表现 |
| --- | --- | --- |
| 视觉中心缺失 | 图表、指标和结论像三个并列小卡 | 价格走势成为中心，指标和结论作为辅助证据 |
| 信息同权重 | 多个方框、标题和小字强度接近 | 形成主结论、验证证据、补充信息三层 |
| 数据能力未编排 | 行情、K 线、新闻和历史能力散落在抽屉或深研区 | 随候选切换加载到同一研究档案 |
| 缺口被版式掩盖 | 没有机构参与等数据，却保留相似卡位 | 合同缺失时显示收缩空态，并说明解除条件 |

## 三、目标效果

在基准桌面视口中，用户进入页面后无需滚动即可完成以下判断：当前观察日和使用边界是什么，候选池中先看谁，当前标的价格与趋势是否确认，关键基本面与因子是否支持，主要风险和失效条件是什么，下一步只能进行哪一种研究动作。

最终页面保留参考稿的终端式构图，但不复制其虚构数据：左侧是候选池，中部是当前标的研究档案，右侧是风险与行动，底部是研究审计日志。中部不再由一组平均卡片组成，而按“价格验证、关键数据、综合结论、研究证据、因子判断、事件与基本面”逐级展开。

## 四、页面结构

### 4.1 固定桌面骨架

现有三栏与审计区几何已经基本可用，本轮不再推倒外框。基准视口下保持以下结构，并把主要精力投入内部信息层级。

| 区域 | 基准尺寸或比例 | 作用 |
| --- | --- | --- |
| 顶部工具条 | 48px 高 | 页面名、观察日、搜索、市场、行业、信号、研究视图、助手和刷新 |
| 左侧候选池 | 312px | 候选排序、日涨跌、评分、状态和选中态 |
| 中部研究档案 | 710px 级 | 价格、指标、结论、证据、因子、事件和基本面 |
| 右侧风险行动栏 | 256px 级 | 硬门槛、风险标签、证据来源、下一步动作和备注 |
| 底部审计台账 | 全宽 | 数据日、事件类型、标的、证据、状态和操作者 |

桌面主区只允许候选列表和审计表在数据超量时局部滚动；中部研究档案和右侧栏不得依赖内部滚动才能完成首屏任务。窄屏按现有全站布局合同折叠，不通过压缩到 11px 以下维持三栏。

### 4.2 顶部工具条

顶部只保留对全页生效的上下文和操作。观察日、搜索、市场、行业、信号和研究视图必须是真实控件，筛选只改变当前可见候选，不得改变后端返回的候选成员、权威顺序和总数。数据状态、策略门禁和使用边界使用最多三个紧凑状态项，不得与筛选器混排成第二套工具条。

刷新只重新读取和重算已授权的观察型结果。复核助手不得产生交易指令，也不得把 `observational_only` 改写为可执行。

### 4.3 左侧候选池

每行固定展示排名、代码与名称、后端评分或 `—`、当日涨跌和观察状态。行内不再重复行业胶囊、来源标签和多段说明；完整原因进入中部档案或抽屉。选中态使用左侧强调线和低对比背景，不使用大面积高亮。

候选池必须严格遵循 `first_screen.review_queue` 的成员、顺序、数量和复合身份。搜索、行业和信号筛选只能过滤可见行；恢复筛选后顺序必须与接口一致。页面显示真实总数，不能把参考稿的 `358` 写成静态文案。

### 4.4 中部研究档案

中部是本轮重建重点，固定为以下七层。

| 层级 | 内容 | 数据来源 | 表现要求 |
| --- | --- | --- | --- |
| 标的头 | 名称、代码、价格、涨跌、成交与观察元数据 | workbench 候选 + stock detail | 名称和价格是首要视觉锚点 |
| 研究页签 | 概要、基本面、估值、动量、事件、财务、附录 | 同一选中标的上下文 | 页签必须真正切换内容，不做静态装饰 |
| 首要验证带 | 价格走势、关键数据、综合结论 | stock detail candles/factor + 候选证据 | 价格图约占 40%，结论不低于关键数据权重 |
| 研究与证据带 | 研究观点、最新信号、主证据和补充证据 | review queue + signal confluence | 观点、事实和边界分开，不拼成一段长文 |
| 八因子带 | 综合、估值、质量、动量、情绪、拥挤度、流动性、波动率 | 已有候选字段或明确缺值 | 固定八个等宽单元，不允许空白第九列 |
| 下部验证区 | 事件时间线、财务估值、证券来源与时点 | candidate history、news、stock detail | 宽度不等分，按信息重要性分配 |
| 扩展可视化 | 因子表现、机构参与 | 新合同 | 合同未完成前不画假图，使用收缩空态 |

价格图使用 `LivermoreStockDetailPayload.candles`，展示真实收盘、MA5、MA20，并在数据足够时增加成交量子图；K 线观察结论使用 `StockKlineAnalysisPayload`，前端不自行重新判形态。PE、PB、ROE 和股息率优先使用 `LivermoreStockDetailFactor`，候选原始字段只能作为有来源标识的补充，不得覆盖详情合同。

综合结论只允许由现有门禁状态、候选原因码、主证据、失效条件和数据状态组装。它必须明确区分“事实”“研究判断”和“使用边界”，不能输出买入、卖出、仓位或正式配置建议。

### 4.5 右侧风险与行动

右栏只回答“为什么还不能继续”和“下一步能做什么”。硬门槛最多四条，每条包含状态、原因和解除条件；风险标签只保留与当前标的相关的三到五项；证据来源显示来源、数据日和模块状态，不展示无助于业务判断的接口长路径。

当前观察边界下，唯一主操作为“开始深度研究”。次操作可以是打开详情抽屉、加入自选和查看历史表现；不得出现买入、卖出、调仓、下单或批准。备注属于研究留痕，不得伪装成正式审批意见。

### 4.6 审计日志

审计区记录页面实际发生的观察事件，包括候选选择、证据读取、筛选变化、研究备注和模块状态变化。派生行没有权威时间时显示 `—`，操作者没有权威身份时显示“系统”或 `—`，不得复制第一条接口时间充当所有事件时间。

## 五、数据合同处理

现有仓库已经具备多数核心数据，第一阶段不需要先造一套新后端。

| 页面能力 | 当前来源 | 状态 | 实施处理 |
| --- | --- | --- | --- |
| 首屏结论与候选 | `GET /ui/market-data/stock-analysis/workbench` | 可用 | 继续作为唯一首屏主包 |
| 60日价格与估值因子 | `/ui/market-data/livermore/stock-detail` | 可用 | 候选选中后按需读取，进入中部档案 |
| K线观察 | `/ui/market-data/stock-analysis/kline-analysis` | 可用 | 复用后端状态、形态和有效性判断 |
| 候选历史 | `/ui/market-data/livermore/candidate-history` | 可用 | 进入事件和历史验证区 |
| 新闻与事件 | Choice news/event client | 部分可用 | 按标的和观察日读取，保留 future-row 排除状态 |
| 策略评分与优化 | strategy score/optimization | 诊断型 | 明确标记代理或观察，不升级为正式结果 |
| 代理回测 | cycle/portfolio proxy backtest | 代理型 | 延迟加载并保留 proxy 披露 |
| 因子表现序列 | 无稳定页面合同 | `PENDING` | 单独定义日期、基准、收益口径和版本 |
| 机构参与结构 | 无股票页权威合同 | `PENDING` | 单独确认数据源、日期、持仓口径和责任人 |

`docs/page_contracts.md` 当前没有 `/stock-analysis` 的独立正式条目。实施前必须新增 GAP 页面合同段，至少登记路由、业务问题、必有区块、主接口、状态边界、必显字段、非目标和验收测试。该登记只描述观察型页面，不创建 `PAGE-STOCK-*` 或 `MTR-STOCK-*`，也不改变 `formal_use_allowed=false`。

## 六、交互与状态规则

用户切换候选后，中部档案和右栏必须共享同一个股票代码和观察日。旧候选的迟到请求不得覆盖新候选；请求键至少包含股票代码、实际观察日和 lookback。切换期间保留档案骨架，并明确显示局部加载状态，不能让整页闪回空白。

五类数据状态必须在受影响区块附近可见。

| 状态 | 页面处理 |
| --- | --- |
| loading | 使用接近真实高度的骨架，不改变整体几何 |
| empty | 收缩为空态，说明当前合同没有记录 |
| error | 保留其他有效模块，只在失败区提供重试 |
| stale/fallback | 显示实际数据日和降级原因，并收紧结论文案 |
| partial | 显示已有结果和缺失项，不把部分成功写成就绪 |

缺值统一使用 `—`。`0` 必须显示为零，不能与缺失合并。正式数值只由后端返回，前端仅做格式化、排序和视图筛选。

## 七、实施工作包

### WP-0：页面合同与参考基线

在 `docs/page_contracts.md` 补充观察型股票页合同，冻结参考图、当前图和固定基准视口。形成一张“参考区块、当前组件、数据来源、目标组件”的映射表，并把数据差异与 CSS/布局差异分开记录。

产出包括页面合同、同尺寸基线图、可见区域几何清单和不可伪造数据清单。WP-0 完成前不进入全面样式开发。

### WP-1：研究档案视图模型

把目前散落在 `StockAnalysisPageImpl.tsx` 中的候选字段探测、结论组装、图表配置和证据拼接迁移到页面域内视图模型。视图模型只接受已定义的 workbench、stock detail、K 线、新闻和历史 DTO，不继续扩张 `Record<string, unknown>` 式的宽松探测。

计划新增 `stockAnalysisResearchDeskModel.ts`，统一生成标的头、关键指标、研究结论、八因子、风险门槛、事件和审计行。格式化优先复用 `src/pageModel`、`src/utils/format.ts` 和 `src/utils/tone.ts`。

### WP-2：中部档案组件重建

将当前大组件拆成可独立验收的档案区块，但不抽象成全局基础设施。建议拆分为价格验证、关键数据、综合结论、研究证据、八因子、事件时间线和基本面七个页面域组件。

这一步完成后，页面应当首先像研究终端，而不是卡片墙。价格图需要真实占据首屏中心，结论和证据建立明确的阅读顺序，次级模块通过分隔线和留白组织，不继续层层套卡。

### WP-3：真实数据编排

复用现有选中候选查询，把 stock detail、K 线分析、候选历史和 Choice 事件接入同一研究档案。查询仍按需执行，首屏 workbench 主包不等待这些详情；选中首个候选后再加载详细档案。

所有模块需要记录实际观察日、状态和来源。发生 as-of 不一致时，相关模块显示错配并退出结论组装，不允许前端静默合并不同日期的数据。

### WP-4：候选池、右栏和审计收口

候选池删去重复说明，保留可扫读的五列。右栏改成硬门槛、风险标签、来源、动作和备注的固定顺序。审计日志使用真实事件和结构化日期，不再用派生时间补齐空值。

这一步只调整当前股票页，不触碰首页、组合页、全局状态架构和共享 SDK。

### WP-5：缺失金融合同

因子表现序列和机构参与结构分别提交数据合同提案。合同至少需要定义业务含义、日期、单位、基准、来源、更新频率、空值、版本、责任人和可否进入研究结论。合同未批准前，对应模块维持收缩空态；不得用代理持仓数量、北向资金标签或前端生成环图冒充机构参与。

### WP-6：测试与视觉验收

先运行视图模型和组件测试，再运行股票页合同、尺寸守卫、类型检查、ESLint 和前端债务审计。最后在用户当前使用的浏览器中完成真实筛选、候选切换、页签、抽屉、空态、错误态和刷新验证。

视觉验收必须将参考图和实现图裁成相同尺寸后并排判断。截图分数只能作为辅助，不能替代业务层级、数据来源和交互可用性验收。

## 九、验收标准

### 9.1 业务闭环

- 用户在首屏能够说出观察日、使用边界、当前标的、主结论、主要风险和下一步。
- 候选成员、顺序和数量与 `first_screen.review_queue` 完全一致。
- 价格、估值、K 线、事件和历史数据可以追溯到相同股票代码与观察日。
- stale、fallback、partial、error 和 as-of 错配不会被渲染为可继续推进。
- 页面不出现交易、配置、下单或批准语义。

### 9.2 视觉与交互

- 在 `1440×900` 和参考可见区同尺寸基准下，顶部、三栏和审计区无重叠、无页面级横向滚动。
- 50% 缩放时仍能分辨标的头、价格验证、综合结论、风险行动和审计五个层级。
- 数据行文字不低于 12px，数字使用 tabular，正文与辅助文字有清楚的三级对比。
- 面板嵌套不超过两层，同级内容优先使用分隔线和留白，不形成连续格子墙。
- 顶部全部筛选、研究页签、候选选择、详情抽屉和主操作可以真实使用。
- 右栏不出现内部滚动；候选池和审计表只有在内容超量时局部滚动。

### 9.3 合同与质量

- `route -> client -> DTO -> query -> view model -> component` 路径可以逐项核对。
- 正式金融计算的前端新增数量为零。
- 每个可见指标区分 `null`、零、缺失、过期、回退和错误。
- 定向 Vitest、类型检查、ESLint、`debt:audit`、编码审计和 `git diff --check` 全部通过。
- 同尺寸视觉复核中不存在结构级阻断；真实数据差异必须单列，不能被算作 CSS 成功，也不能通过伪造数据消除。

## 十、实施顺序与预期效果

建议先完成 WP-0 至 WP-4，形成“现有数据条件下的完整研究终端”。这一阶段不等待新数据合同，能够直接解决当前页面像卡片拼装、阅读主线不清、图表权重不足和详情能力散落的问题。

WP-5 独立推进。因子表现和机构参与合同获批后，再补参考稿对应的专业可视化。这样可以避免前端为了截图相似而制造第二套金融真相，也不会阻塞主体页面重建。

完成 WP-0 至 WP-4 后，用户看到的差异应当是结构性的：第一眼先看到标的和价格验证，第二眼得到综合结论与失效条件，第三眼进入事件、基本面和证据；右侧始终保留风险门槛和唯一下一步。页面不再依靠更多卡片显得专业，而是依靠完整研究顺序显得专业。

| 风险 | 控制 |

| 再次把栏宽相似当成完成 | 验收必须覆盖业务主线、真实交互和数据来源 |
| 为补参考图而伪造金融模块 | 缺合同模块只允许收缩空态和 `PENDING` |
| 详情查询拖慢首屏 | workbench 先渲染，选中标的详情按需加载并缓存 |
| 页面继续膨胀 | 派生逻辑进入页面域视图模型，区块组件保持单一职责 |
| 日期和版本静默错配 | 查询键和视图模型同时校验股票代码、观察日和来源状态 |
| 越过观察边界 | 所有动作词和状态继续受 `observational_only` 限制 |

## 十二、放行建议

建议立即批准 WP-0 至 WP-4 的页面重建；它主要复用现有合同，不需要修改受保护的数据库、权限、队列或全局状态架构。WP-5 只批准合同设计，不默认批准新数据接入或正式指标晋级。

本轮完成标准不是“看起来像参考稿”，而是“参考稿的研究决策顺序已经由真实数据和真实交互实现”。只有满足这一标准，股票页才能从结构草稿升级为可用的机构研究终端。
