## 1. 旧口径缺陷(已确认)

### 1.1 uptrend_momentum(现行 L181-187)

```
score = return_20d*0.35 + return_60d*0.30 + return_120d*0.15
      + min(amount_ratio/2, 1)*0.10
      + max(0, 1 - close_to_ma20/0.20)*0.10
```

各收益分量准入上限不同(`MAX_RETURN_20D=1.00 / 60D=1.50 / 120D=3.00`),名义权重与实际最大贡献失配:

| 分量 | 名义权重 | 准入上限 | 实际最大贡献 | 失真倍数 |
|---|---|---|---|---|
| return_20d | 0.35 | 1.00 | 0.350 | 1.00x |
| return_60d | 0.30 | 1.50 | 0.450 | 1.50x |
| return_120d | 0.15 | 3.00 | **0.450** | **3.00x** |
| 量比 | 0.10 | ratio∈[0.8,3.0] | 0.100(ratio≥2 饱和) | — |
| MA20 贴近度 | 0.10 | cm20∈(0,0.2] | 0.100 | — |

120 日收益的实际影响力是名义权重的 3 倍,与 20 日分量并列最大贡献 0.45,与"0.35/0.30/0.15 递减"的设计意图相反。旧分数值域上限 1.45。

### 1.2 fresh_trend_watchlist(现行 L225-233)

```
score = return_20d*0.40 + return_60d*0.28 + return_120d*0.14
      + min(amount_ratio, 2.5)*0.08
      + min(turn/10, 1)*0.06
      + board_bonus                       # 300/301/688:+0.10;002:+0.04
      - max(close_to_ma20 - 0.16, 0)*0.30 # 罚项,最大 0.027
```

| 分量 | 名义权重 | 准入上/界 | 实际最大贡献 | 失真倍数 |
|---|---|---|---|---|
| return_20d | 0.40 | 0.90 | 0.360 | 0.90x |
| return_60d | 0.28 | 1.60 | 0.448 | 1.60x |
| return_120d | 0.14 | 3.20 | **0.448** | **3.20x** |
| 量比 | 0.08 | min(ratio,2.5) | **0.200** | **2.50x** |
| 换手 | 0.06 | 已归一 | 0.060 | 1.00x |

两处失真:收益分量同 uptrend;**量比分量未归一**,实际最大贡献 0.20 是名义 0.08 的 2.5 倍。旧分数值域上限 1.616。

### 1.3 两模块量比归一化不一致

- uptrend:`min(ratio/2, 1)*0.10` —— ratio=2.0 即饱和(准入上限 3.0,上段 1/3 区间无区分度);
- fresh:`min(ratio, 2.5)*0.08` —— 线性到 2.5 饱和,且未先归一。

同一个"量能确认"语义,两模块斜率、饱和点、有效权重全部不同。规范样板 `mean_reversion_candidates.py` 全分量 [0,1] 后加权(`abs(dd20)*0.4 + close_strength*0.3 + min(vol_ratio/3,1)*0.3`),本方案向其对齐。

## 2. 统一方案(旁路设计,未落地)

原则:**每个分量先归一到 [0,1],再乘名义权重**,使名义权重 = 实际最大贡献。

### 2.1 新公式

uptrend(值域上限 1.00):

```
score_v2 = min(max(r20,0)/1.00, 1)*0.35
         + min(max(r60,0)/1.50, 1)*0.30
         + min(max(r120,0)/3.00, 1)*0.15
         + min(amount_ratio/2.5, 1)*0.10
         + max(0, 1 - close_to_ma20/0.20)*0.10
```

fresh(核心值域上限 0.96,加 bonus 后 1.06):

```
score_v2 = min(max(r20,0)/0.90, 1)*0.40
         + min(max(r60,0)/1.60, 1)*0.28
         + min(max(r120,0)/3.20, 1)*0.14
         + min(amount_ratio/2.5, 1)*0.08
         + min(turn/10, 1)*0.06
         + board_bonus
         - max(close_to_ma20 - 0.16, 0)*0.30
```

收益分量分母 = 各自模块的准入上限(clip 为防御,准入过滤已保证不越界)。

### 2.2 量比统一公式:推荐 `min(amount_ratio/2.5, 1)`

理由:

1. **对 fresh 是纯尺度变换**:`min(ratio,2.5)/2.5 ≡ min(ratio/2.5,1)`,分量内部排序与形状完全不变,只是权重回到名义 0.08;
2. **对 uptrend 恢复区分度**:饱和点从 2.0 移到 2.5,原先 ratio∈[2.0,3.0] 的平台区(占准入域 1/3)恢复线性区分,仅 [2.5,3.0] 保留饱和(温和放量优于极端放量的业务假设不变);
3. 2.5 落在两模块准入域([0.8,3.0] / [0.7,3.5])内部,单一公式两处适用。

备选:保留 uptrend 的 `min(ratio/2,1)` 并让 fresh 迁就——不推荐,因为它会同时改变 fresh 分量形状(饱和点 2.5→2.0)且保留过早饱和的缺点。

### 2.3 board bonus / penalty 处理

- **罚项(伸展惩罚)**:保持原样。它是门槛型惩罚(cm20>0.16 才生效,最大 0.027),不是 [0,1] 分量,归一化会改变其"超阈值线性惩罚"语义。
- **board_bonus**:v2 保持 +0.10/+0.04 不变,但需知晓其**相对影响力会随分数压缩而变化**:002 与 300/688 板的 0.06 分差,旧口径折合 r120 差 0.43(0.06/0.14),新口径折合 r120 差 1.37(0.06/0.04375)——对长窗收益的"补偿力"放大约 3.2 倍;折合 r20 差则由 0.15 变 0.135,基本持平。fresh 本就限定成长板(300/301/688/002),bonus 实际只区分 002 与非 002,模拟显示未造成异常集中;若未来希望 bonus 也纳入统一框架,可改写为权重 0.10 的 [0,1] 分量(300/301/688→1.0,002→0.4),v2 不动。
- 建议在 v2 payload/文档中明确:核心加权分满分 1.00(uptrend)/0.96(fresh),bonus/penalty 为核心分之外的调整项。

- 输入 SQL 复刻服务层 `_load_uptrend_momentum_snapshots` / `_load_fresh_trend_watchlist_snapshots`:`choice_stock_daily_observation` 当日行 + ≤130 根历史(仅 trading 状态,`TRADING_STATUS_VALUES` 同词表),金额经 `amount_rmb_sql` 归一为元;

| 差异 | 原因 | 影响 |

## 11. 实施要求与建议

### 11.1 明确建议:**推荐实施**

理由:

1. 缺陷是实质性的——120 日收益实际影响力 3 倍于名义、fresh 量比实际权重 2.5 倍于名义,权重语义失真且两模块口径互不一致;
2. 影响可控且方向正确——排序结构高度保留(Spearman 0.95~0.98),集合替换集中在"靠尺度失真受益"的 120 日大涨股(§6 方向验证);
3. 两策略均为 observation_only,无融合/交易下游,当前市场转弱期(池规模小、J=1 天数多)是切换窗口;
4. 维持现状的成本:失真会继续累积进候选历史,且与 mean_reversion 样板口径的分裂会被后续策略继承。

### 11.2 实施清单(仓库规约要求)

1. **FORMULA_VERSION 升级**:`rv_uptrend_momentum_candidates_v1 → v2`、`rv_fresh_trend_watchlist_candidates_v1 → v2`(payload 已带 formula_version 字段,前端/历史可辨识);
2. **黄金样本测试**:落地 §9 两表为精确断言(现有测试仅 `assert score > 0`,无法约束公式——见 §12);边界样本(U5/U6 同分、F1 罚项恰零、F3 双边界)必须包含;
3. **影响报告**:本报告可直接作为变更影响附件;
4. **历史断代标注**:candidate history 写入侧在 evidence JSON 中加入模块级 `formula_version`(修复 §7 暴露的治理缺口:历史行无法自证生成公式版本);**不回改存量历史行**;
5. **uptrend 回填漂移单独立项**:2026-03-25~06-15 的 1170 行 uptrend 存量 score 与自身分量不自洽(§7),与本次统一无关但会污染任何跨期 score 分析,建议登记数据质量问题并在读取侧按 fv 断代;
6. 服务层无需改动(加载 SQL、过滤、排序、板块上限均不变);前端无需改动。

### 11.3 风险与缓解

| 风险 | 幅度 | 缓解 |
|---|---|---|
| 榜单换血引起使用者困惑 | Top-30 中位换 3 只、Top-20 中位换 4 只,Top1 约 37%~40% 天数更换 | 版本字段 + 发布说明;切换日在候选历史中天然留痕(formula_version) |
| fresh 量比影响力下降是行为变化(非纯 rescale) | 量比分量满贡献 0.20→0.08 | 属设计意图(名义权重回归);若业务复核后认为量能应保持强影响,可在 v2 把名义权重定为 0.12~0.15 并重跑本模拟,**不应**回到未归一形态 |
| bonus 相对长窗收益的影响力放大(§2.3) | 0.06 分差折合 r120 当量 0.43→1.37 | fresh 本就仅限成长板,模拟未见板块异常集中;保留观察 |
| 历史 score 跨版本误用 | — | 断代标注(11.2-4);evidence JSON 内 score 与 formula_version 成对存储 |

## 12. 测试覆盖缺口(现状)

1. `backend/tests/core_finance/test_uptrend_momentum_candidates.py` 与 `test_fresh_trend_watchlist_candidates.py` 仅断言 `score > 0`,**没有任何精确分数断言**——公式改动(如 §7 的漂移)不会被现有测试捕获;
2. 无两模块量比口径一致性的契约测试;
3. 无 candidate history evidence 自洽性(score vs 分量复算)校验,§7 的漂移三个月无人发现;
4. 建议随 v2 落地:§9 黄金样本精确断言 + 排序翻转断言(U2/U3)+ evidence 自洽性抽查(可放 tests 的数据质量层)。
